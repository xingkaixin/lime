# Files, Projects & Session

Lime handles file loading, encoding and indentation detection, atomic saving, project folder watching, and Sublime Text-style hot exit across windows and restarts.

## File Opening, Kind Detection & Large Files

- **OS open-file delivery**: File opening handles `mygo.App.OnOpenFile` in addition to `os.Args`, because macOS Finder, Dock drops, and `open(1)` deliver file paths through the OS callback rather than CLI arguments (`cmd/lime/main.go`).
- **CLI `file:line:col` coordinates**: CLI column arguments are 1-based rune indices and are converted to 0-based UTF-8 byte offsets for `editor.Pos.Col` (`cmd/lime/safety_test.go`).
- **Image preview formats**: `imageExts` (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.bmp`) is scoped specifically to the formats decoded by MyGo's `ui.DecodeBitmap` (`cmd/lime/preview.go`).
- **Binary and file-kind detection**: `fileKind` classifies files as images by extension, binary if a NUL byte appears in the first 8,000 bytes (matching Git's heuristic), and text otherwise (`cmd/lime/preview.go`). Commit diff text uses the same 8,000-byte NUL check in `binary` (`cmd/lime/commitview.go`).
- **UTF-16 BOM exemption**: Files starting with a UTF-16 BOM (`0xFF 0xFE` or `0xFE 0xFF`) are classified as text before the NUL-byte check because UTF-16 contains NUL bytes for most ASCII characters (`cmd/lime/preview.go`).
- **Single-pass sniff boundary**: Single-pass file loading sniffs the first 8,000 bytes for binary detection before reading the remainder, so multi-chunk read tests use fixtures larger than 8,000 bytes (`cmd/lime/safety_test.go`).
- **Zero-extra-copy file reads**: `readText` streams file contents into a pre-sized `strings.Builder` instead of calling `string(os.ReadFile(path))`, eliminating a full-file copy on large files (`cmd/lime/app.go`).
- **Large-file threshold**: At or above `largeFile` (16 MiB), files skip gutter diffing (`DiffBase`) so the editor does not retain a second copy of the text or run line-by-line diffs on open and save (`cmd/lime/app.go`).
- **Markdown local file sandboxing**: `localFile` restricts Markdown preview image and file reads to local regular files, rejecting Windows volume names longer than 2 characters (such as `\\host\share`, `\\?\`, and `\??\UNC\host`) to prevent credential leaks or device access, and checking `IsRegular` to avoid hangs on special files like `/dev/zero` (`cmd/lime/mdpreview.go`).
- **Windows drive-letter links**: On Windows, paths like `C:\docs` parse with a non-empty `url.URL.Scheme`, so `followLink` permits non-empty schemes when `filepath.IsAbs(path)` is true while still rejecting unknown URI schemes (`cmd/lime/mdpreview.go`).

## Encodings, Line Endings & Indentation

- **Encoding names and in-memory UTF-8**: `fileEncoding` uses Sublime Text's exact encoding names for settings and session compatibility, while editor buffers always store text as UTF-8 in memory regardless of the on-disk encoding (`cmd/lime/encoding.go`).
- **Default fallback encoding**: `defaultFallback` is `Western (Windows 1252)`, matching Sublime Text's default `fallback_encoding` (`cmd/lime/encoding.go`).
- **Lossless decode verification and passthrough**: `decode` strips the encoding's BOM and verifies that re-encoding produces the original bytes, because `x/text` decoders map unrepresentable bytes to `U+FFFD` and would corrupt the file on save (`cmd/lime/encoding.go`). When a detected encoding cannot round-trip losslessly, `openText` falls back to `utf8Encoding` with the untouched raw bytes so saving preserves them verbatim (`cmd/lime/encoding.go`).
- **Encoding retention on reload**: `reopenText` keeps a document's existing encoding `e` if BOM/UTF-8 detection agrees—or if the reloaded bytes are pure ASCII (which would otherwise detect as UTF-8) and `e` round-trips losslessly—and falls back to `openText` otherwise (`cmd/lime/encoding.go`).
- **Strict UTF-8 validation on encode**: `encode` prepends the encoding's BOM and explicitly rejects non-UTF-8 buffer bytes before calling `x/text` encoders, preventing `x/text` from silently writing `U+FFFD` on save (`cmd/lime/encoding.go`).
- **Unrepresentable-character save fallback**: Matching Sublime Text, if the chosen encoding cannot represent a character in the document, saving writes the file as UTF-8 and notifies the user instead of failing or dropping characters (`cmd/lime/app.go`).
- **Dirty-buffer reopen guard**: `reopenable` disallows Reopen with Encoding on dirty buffers, matching Sublime Text so unsaved edits cannot be silently discarded (`cmd/lime/encoding.go`).
- **Line ending identifiers**: `lineEnding` uses Sublime Text's `set_line_ending` command types (`"windows"`, `"unix"`, `"cr"`), which are also persisted in `session.json` (`cmd/lime/format.go`).
- **Line-ending dirty tracking and CR-only files**: `savedEnding` is tracked separately because `editor.Buffer.SetLineEnding` mutates line endings without incrementing `Buffer.Version()`; bare `\r` files are tracked with a `cr` flag because `splitLines` normalizes `\r` to `\n` in the buffer and `writeIn` converts back on save (`cmd/lime/app.go`).
- **Indentation scan limit**: `guessLines` caps indentation detection at 10,000 lines so opening large files stays fast (`cmd/lime/indentation.go`).
- **Sublime Text indentation heuristic**: `guessIndent` mirrors Sublime Text's `detect_indentation`: it selects tabs when more lines start with a tab than spaces, otherwise picks the most common space indent step from the preceding line, returning `IndentAuto` when no lines are indented and size `0` when width cannot be inferred (`cmd/lime/indentation.go`).
- **Single-space exclusion**: Single-space leading indents and 1-space indent steps are ignored during detection because a single leading space is more commonly block comment alignment (`" * "`) than indentation (`cmd/lime/indentation.go`).

## Dirty Tracking, External Changes & Safe Saving

- **Per-version dirty cache**: `doc.dirty()` caches its result in `(checked, modified)` per buffer version so buffer text is compared against the saved snapshot at most once per edit version instead of on every frame (`cmd/lime/app.go`).
- **Chunked snapshot comparison**: `sameText` compares two editor snapshots chunk-by-chunk using `Snapshot.Chunks` and `iter.Pull` rather than materializing full strings, avoiding large allocations on big files (`cmd/lime/app.go`).
- **External modification stamp**: On-disk changes by external apps are detected with a `(modTime, size)` stat `stamp` modeled on Sublime Text's file-reload check (`cmd/lime/app.go`). External-modification tests advance `mtime` by 2 seconds via `os.Chtimes` to remain reliable on filesystems with coarse 1–2 second granularity (`cmd/lime/safety_test.go`).
- **Revert-only Unsaved Changes diff**: `showUnsavedChanges` compares a buffer against its file on disk and exposes only a Revert action, omitting Keep/Accept because accepting onto the disk side would imply saving, which must only happen via Save (`cmd/lime/compare.go`).
- **Main-thread save execution**: `write()` runs on the main thread so buffer tidying, snapshot capture, atomic file writing, and `MarkSaved` stay synchronized with UI state (`cmd/lime/app.go`).
- **Single-step save tidying**: `tidy` wraps save-time edits (trim trailing whitespace and ensure trailing newline) in one `Buffer.Transact` so both mutations undo together as a single undo step (`cmd/lime/app.go`).
- **Symlink-preserving atomic writes**: `writeFileAtomic` resolves symlink targets before creating the temporary file and calling `os.Rename`, so atomic saves update the target file rather than replacing the symlink itself (`cmd/lime/app.go`).
- **Linux POSIX ACL cleanup**: On Linux, if the original file has no POSIX access ACL (`ENODATA`), `system.posix_acl_access` is explicitly removed from the temporary file because it may have inherited a default ACL from its parent directory (`cmd/lime/save_linux.go`).

## Projects, File Operations & Filesystem Watching

- **JSONC project parsing**: `projStripJSONC` strips UTF-8 BOMs, `//` line comments, `/* */` block comments, and trailing commas from Sublime Text's JSONC `.sublime-project` files while leaving string literals untouched before parsing with `encoding/json` (`cmd/lime/project.go`).
- **Round-trip project preservation and relative paths**: `projectFile` reads only folder paths while retaining all other top-level and per-folder fields as raw JSON so Sublime Text settings and build systems survive edits (`cmd/lime/project.go`). `saveProject` writes folder paths relative to the `.sublime-project` file (matching Sublime Text) while preserving unknown fields (`cmd/lime/project.go`).
- **Default exclude patterns**: Default `folder_exclude_patterns`, `file_exclude_patterns`, and `binaryFiles` mirror Sublime Text's exclude lists, with `binaryFiles` additionally omitted from Goto Anything and file search while remaining visible in the side bar (`cmd/lime/project.go`).
- **Non-destructive file rename**: `renameNew` refuses to overwrite a different existing file (unlike `os.Rename`), while allowing case-only renames on case-insensitive filesystems when `os.SameFile` confirms source and destination are the same file (`cmd/lime/project.go`).
- **Self-containment Replace guard**: When moving or copying an item that lies inside the colliding destination folder (`within(path, to)`), Replace is removed from the collision dialog because trashing the destination folder first would also destroy the source item (`cmd/lime/project.go`).
- **Finder-style collision naming**: `keepBoth` resolves name collisions using macOS Finder's Keep Both convention, appending a space and the first unused integer starting at 2 before the file extension (`cmd/lime/project.go`).
- **Windows watching fallback**: Live side bar directory watching is disabled on Windows (`watchDirs = runtime.GOOS != "windows"`) because Windows directory watches hold open handles that block renaming or moving ancestor folders; on Windows, cached directory listings are invalidated on window focus instead (`cmd/lime/project.go`).
- **Collapsed folder unwatching**: Collapsed side bar folders are unwatched to avoid unnecessary watchers and are re-read from disk when reopened (`cmd/lime/main_test.go`).
- **Watch lifecycle and cancellation race guard**: `watchDir` stores a watch entry before calling `WatchFiles` and keeps it on startup failure so a failing directory is not retried on every render frame; a running watch that terminates later (such as when the directory is deleted) drops both the entry and cached listing so the directory will be re-read and re-watched if shown again (`cmd/lime/project.go`). Inside the main-thread `ended()` callback, `ctx.Err() != nil` guards against mutating state after the watch was explicitly cancelled or replaced (`cmd/lime/project.go`).
- **Batched watch refresh**: `projWatchBatch` coalesces and debounces filesystem watch event bursts across a window's watched folders for 150 ms before invalidating directory caches, refreshing git marks, re-indexing Goto Anything, or reloading externally modified tabs (`cmd/lime/project.go`).

## Recent Items & Project Switching

- **Session-backed recent history**: `recentList` stores recent files and recent folders/`.sublime-project` paths newest-first inside `session.json`, matching Sublime Text (`cmd/lime/recent.go`). Open Recent lists up to 8 files and 8 folders (matching Sublime Text), while up to 30 folders/projects are retained in memory and session state for Quick Switch Project (`cmd/lime/recent.go`).
- **OS recent-documents filtering**: `addRecent` registers only files—not folders or `.sublime-project` files—with the OS recent-documents list (macOS Dock menu and Windows jump list), because the OS opens selections via `OnOpenFile`, which adds folders to the last-focused window and opens `.sublime-project` files as plain text instead of switching projects (`cmd/lime/recent.go`).
- **Project switching without workspace files**: Because Lime has no `.sublime-workspace` files to swap a window's tabs in place as Sublime Text does, `switchProject` focuses an existing window holding the target folder or `.sublime-project`, reuses the current window only if it has no project/folders and no unsaved tabs, and opens a new window otherwise (`cmd/lime/recent.go`).

## Hot Exit, Window Closing & Session Persistence

- **Hot-exit session contents**: `session.json` persists windows, layouts, folders, open tabs (including unsaved buffer contents), and recent items across runs, matching Sublime Text's hot exit (`cmd/lime/session.go`).
- **Window-close semantics**: Closing a non-last window prompts to save dirty tabs because they would otherwise be lost; closing the last window persists the session without prompting—quitting on non-macOS and keeping the process alive in the Dock on macOS (`cmd/lime/app.go`). Tests that verify save prompts open a second window so `closing()` prompts rather than taking the last-window hot-exit path (`cmd/lime/safety_test.go`).
- **Quit persistence and failure guard**: `quit` persists settings and all windows (including unsaved buffers) without save prompts, and cancels the quit via `PreventDefault` if session persistence fails so unsaved edits are never lost (`cmd/lime/app.go`).
- **Zero-window macOS quit and Dock reopen**: When quitting on macOS with no open windows (`len(l.wins) == 0`), `keep()` preserves the session saved when the last window closed instead of overwriting `session.json` with an empty session (`cmd/lime/app.go`). Clicking the macOS Dock icon calls `reopen()` to restore that saved session, or opens a fresh window with an untitled tab if none exists (`cmd/lime/app.go`).
- **Excluded transient tabs**: Diff, commit, find-in-files, and Markdown preview tabs are omitted from `session.json` because their content is owned by other tabs, git, or re-run searches (`cmd/lime/session.go`).
- **Asynchronous atomic session writes**: On the main thread, `unsaved` captures only an immutable `*editor.Snapshot`, deferring string materialization into `Text` or `Raw` to `writeSession` on a background goroutine (`cmd/lime/session.go`). `writeSession` rejects stale async writes with a generation guard (`gen < l.written`), writes via a temporary file plus rename for crash atomicity, and reads snapshot text safely off the main thread (`cmd/lime/session.go`).
- **Change-fingerprinted autosave**: `autosave` writes `session.json` in the background as state changes so crashes and unexpected OS restarts do not lose unsaved work (`cmd/lime/session.go`). `sessionChanged` detects changes cheaply by fingerprinting buffer version numbers and tab/layout metadata instead of serializing or hashing full buffer contents (`cmd/lime/session.go`).
- **Non-UTF-8 unsaved bytes**: `sessionDoc` stores non-UTF-8 unsaved text (such as GBK bytes) in a base64-encoded `Raw []byte` field instead of `Text`, because Go's JSON string marshaler replaces invalid UTF-8 sequences with `U+FFFD` (`cmd/lime/session.go`).
- **Per-file indentation and encoding schema**: Zero `TabSize` and `nil` `TranslateTabsToSpaces` (`*bool`) mean a tab follows settings rather than storing a per-file override; `Encoding` uses Sublime Text names and may be absent in sessions written before encoding support (`cmd/lime/session.go`).
- **Undoable restore and missing files**: `restoreDoc` loads the on-disk file first and applies unsaved text via `Buffer.Set` so Undo reverts back to the disk state; missing files with no unsaved text are dropped, and tabs from pre-encoding sessions detect encoding or use `FallbackEncoding` (`cmd/lime/session.go`).
- **Legacy session migrations**:
  - Pre-multi-window `session.json` files are loaded by embedding `sessionWindow` alongside `session` during JSON unmarshaling (`cmd/lime/session.go`).
  - Older sessions lacking `side_bar` (`SideBar`, one of `panelNames`) fall back to the side bar state initialized from `settings.SideBar` (`cmd/lime/session.go`).
  - Tabs without stored per-file indentation (including legacy sessions) run indentation auto-detection on restore when `DetectIndentation` is enabled (`cmd/lime/session.go`).
  - Pre-encoding sessions with `Raw` non-UTF-8 unsaved bytes reopen the on-disk file with `utf8Encoding` rather than decoding via the fallback encoding so the buffer preserves the raw bytes verbatim as it originally held them (`cmd/lime/session.go`).
